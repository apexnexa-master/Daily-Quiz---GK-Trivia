You are a senior mobile/backend architect and gamification systems designer.

I am building a brain-training and mini-game application.

The app currently contains these games:

1. GK Quiz
2. Arrow Puzzle
3. Stroop Rush
4. Synapse Recall / Memory game

More games will be added in the future.

The application has three major gameplay modes:

1. Practice
2. Daily Challenge
3. Quick Brain Workout

I need you to redesign and implement the complete scoring, progression, Brain Score, XP, Daily Goal, Streak, and Leaderboard system.

The most important requirement is FAIRNESS.

Different games have completely different scoring systems and difficulty levels, so raw game scores MUST NOT be directly compared with each other.

For example:

- GK Quiz may produce 9/10
- Arrow Puzzle may produce a time such as 3.2 seconds
- Stroop Rush may produce 740 points
- Synapse Recall may produce a sequence length of 7

These raw values cannot be used directly to calculate a global leaderboard.

The architecture must therefore normalize game performance before using it for cross-game metrics.

Do not create a system where users can easily exploit easy games by repeatedly playing them.

The system should reward:

- actual performance
- consistency
- improvement
- meaningful daily participation
- skill development

It should NOT simply reward:

- number of games played
- number of clicks
- repeatedly playing the easiest game
- spending the most time in the app

==================================================

==================================================

Create four separate concepts:

A. GAME SCORE
B. BRAIN SCORE
C. XP

E. DAILY GOAL

Do not mix them together.

==================================================
2. NORMALIZED PERFORMANCE SCORE
==================================================

Every game must convert its raw result into:

Performance Score = 0–100

This score represents how well the user performed in that specific session.

Each game can have its own formula.

The formula should consider the characteristics that actually matter for that game.

Do not force the same raw formula on every game.

--------------------------------------------------
GK QUIZ
--------------------------------------------------

Possible inputs:

accuracy
question difficulty
response speed

Example conceptual formula:

accuracyWeight = 0.60
difficultyWeight = 0.25
speedWeight = 0.15

Performance Score =
accuracyComponent * 0.60
+
difficultyComponent * 0.25
+
speedComponent * 0.15

The final value must be clamped between 0 and 100.

Do not allow the score to exceed 100.

--------------------------------------------------
ARROW PUZZLE
--------------------------------------------------

Arrow Puzzle MUST NOT be scored purely based on time.

This is extremely important.

An easy puzzle solved in 2 seconds should not automatically beat a hard puzzle solved in 8 seconds.

Every Arrow Puzzle should have a difficulty rating.

Example:

difficulty = 1–10

or

difficultyScore = 0–100

The performance calculation should consider:

- puzzle difficulty
- completion
- completion time relative to expected time for that difficulty
- mistakes
- moves
- hints

For example:

Performance =
difficulty-adjusted efficiency
+
completion quality
+
accuracy
-
mistake penalties
-
hint penalties

Normalize the final result to 0–100.

The expected completion time should depend on puzzle difficulty.

For example:

Easy puzzle:
expected time = 3 seconds

Hard puzzle:
expected time = 10 seconds

A user solving the hard puzzle in 8 seconds should be able to score higher than a user solving the easy puzzle in 2 seconds.

Do not use a simple:

100 - time

formula.

--------------------------------------------------
STROOP RUSH
--------------------------------------------------

Use:

- accuracy
- reaction time
- difficulty
- incorrect answers
- streak/consistency

Example conceptual weighting:

accuracy = 50%
reaction speed = 30%
difficulty = 20%

Normalize the result to 0–100.

Avoid making raw reaction time the only factor.

--------------------------------------------------
SYNAPSE RECALL
--------------------------------------------------

Use:

- maximum sequence length
- accuracy
- difficulty
- mistakes
- response time

Example:

sequence performance = 50%
accuracy = 30%
difficulty = 20%

Normalize to 0–100.

The exact weights can be adjusted later.

==================================================
4. SKILL RATING
==================================================

Each user should have a rating for each cognitive skill.

Example:

Knowledge = 75
Logic = 82
Memory = 67
Speed = 71
Focus = 78

Each skill rating must be between 0 and 100.

Do NOT simply replace the skill rating with the latest game performance.

Instead use a gradual update.

Recommended concept:

New Skill Rating =
Old Skill Rating * 0.85
+
New Performance * 0.15

Example:

Old Logic = 70
New Arrow Puzzle Performance = 90

New Logic =
70 * 0.85
+
90 * 0.15

= 73

This prevents huge jumps.

However, for a brand-new user with very little data, allow faster adjustment.

For example:

First few sessions can use a higher learning rate.

As the number of sessions increases, gradually reduce the learning rate.

==================================================
5. MULTI-SKILL GAME CONTRIBUTION
==================================================

If a game affects multiple skills, divide its contribution using weights.

Example:

Arrow Puzzle:

Logic = 70%
Speed = 30%

If Performance Score = 90:

Logic contribution =
90 * 0.70

Speed contribution =
90 * 0.30

Then update each skill rating separately.

The system must ensure that the sum of game skill weights equals 1.0.

Reject or correct invalid configurations.

==================================================
6. BRAIN SCORE
==================================================

Brain Score is the user's overall cognitive performance indicator.

It is NOT:

- IQ
- total XP
- total games played
- leaderboard score

It represents the user's current demonstrated performance across cognitive skills.

Initially:

Knowledge = 20%
Logic = 20%
Memory = 20%
Speed = 20%
Focus = 20%

Brain Score =
weighted average of skill ratings.

Example:

Knowledge = 74
Logic = 82
Memory = 67
Speed = 71
Focus = 78

Brain Score =
(74 + 82 + 67 + 71 + 78) / 5

= 74.4

Display:

Brain Score: 74

Round appropriately.

==================================================
7. BRAIN SCORE MUST BE SLOW MOVING
==================================================

Do not allow one game to drastically change Brain Score.

Example:

Brain Score = 74

One bad game should NOT cause:

74 → 50

One excellent game should NOT cause:

74 → 95

Skill ratings should change gradually.

The overall Brain Score should therefore also change gradually.

Show trends such as:

+4 this week

rather than dramatic changes after every game.

These values should be configurable from one place.

46. MOST IMPORTANT FINAL REQUIREMENT
==================================================

The final system must create a clear separation:

BRAIN SCORE
=
How well the user is performing cognitively.

XP
=
How much the user has engaged with the app.

DAILY GOAL
=
Whether the user completed today's intended activities.

STREAK
=
Whether the user is consistently returning.

LEADERBOARD
=
How well the user performed in controlled competitive Daily Challenges.

GAME SCORE
=
How well the user performed in one particular game.

These must never be treated as the same thing.

The system should be fair, scalable, resistant to farming, easy to explain to users, and easy to extend when new brain games are added.

Implement the architecture cleanly and production-ready.
