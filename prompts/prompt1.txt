Build a polished, production-quality mobile brain-training game called:

SYNAPSE RECALL

Tagline:
"Remember. Rebuild. Repeat."

This game is part of my BRAINX brain-games app.

The goal is to create a game that feels like it was designed by a professional mobile game/UI team—not a basic prototype.

The game should be visually premium, highly understandable, satisfying to play, replayable, and consistent with the existing BRAINX visual identity.

============================================================
1. CORE GAME CONCEPT
============================================================

Synapse Recall is a visual working-memory game.

The player is shown a sequence/pattern of abstract visual objects for a short period.

The objects disappear.

The player must reproduce the correct sequence.

The game starts very simple and gradually introduces more difficult memory mechanics.

IMPORTANT:

Do NOT make the game consist only of colored balls.

Instead use premium abstract geometric symbols/objects.

Examples:

◆
▲
●
✦
⬡
◇
☾
✚
⬢

Each object can have:

- shape
- color
- subtle depth
- subtle glow
- optional position

The visual language should feel futuristic, clean and premium.

Avoid:
- emoji as final production assets
- realistic objects
- photographs
- human faces
- childish cartoon graphics
- generic stock illustrations

Use custom vector/flat-3D style geometric game assets.

============================================================
8. DIFFICULTY PROGRESSION
============================================================

Start extremely easy.

ROUND 1:

Show 3 objects.

Example:

◆ → ▲ → ●

Player recalls:

◆ → ▲ → ●

ROUND 2:

4 objects.

ROUND 3:

5 objects.

ROUND 4:

6 objects.

Continue progressively.

However, difficulty should not rely only on sequence length.

Gradually introduce:

1. Longer sequences
2. Shorter viewing time
3. More visual distractors
4. Similar shapes
5. Different positions
6. Spatial memory
7. Combined shape + color memory
8. More complex patterns

Do NOT introduce all mechanics at once.

The player should feel:

"I can do one more."

not:

"This suddenly became impossible."

18. SCORING
============================================================

Use a fair score system.

Score should consider:

- sequence length
- correct recall
- progression
- accuracy

Longer successful sequences should be worth more.

Do not reward only speed.

Do not create a score that can be exploited by repeatedly playing easy rounds.

Example conceptual values:

3 items → +100
4 items → +130
5 items → +170
6 items → +220
7 items → +280

Add a small perfect-round bonus.

Keep the exact scoring values configurable.

Do not expose the formula to the user.
