IMPORTANT CORRECTION — THE CURRENT IMPLEMENTATION IS WRONG.

The current implementation looks like a heart outline made from thick curved tubes with a few arrows placed inside it.

THIS IS NOT THE INTENDED GAME.

Completely redesign the puzzle-generation and arrow-rendering system.

The game must NOT create the silhouette by tracing its outer boundary with arrows.

The silhouette must be created by DENSELY ARRANGING MANY INDIVIDUAL ARROW PUZZLE PIECES INSIDE THE SHAPE, so that the arrows themselves collectively create the recognizable picture.

==================================================
1. THE MOST IMPORTANT VISUAL RULE
==================================================

THE ARROWS THEMSELVES ARE THE IMAGE.

Do NOT draw an outline of a heart, bird, cat, house, etc. and then put arrows inside it.

Do NOT create one large curved arrow around the perimeter.

Do NOT create smooth tubes following the silhouette boundary.

Do NOT make the arrows look like pipes.

Do NOT use curved arrows simply because the target silhouette is curved.

Instead, take the target silhouette and fill its interior with many individual arrow pieces.

Each individual arrow is an independent puzzle object.

When viewed together, those independent arrows should form the recognizable silhouette.

For example, for a heart:

WRONG:

        ╭────────╮
      ╱            ╲
     │   → → → →    │
     │   ← ← ← ←    │
      ╲            ╱
        ╲        ╱
          ╲    ╱
            ▼

This is just a heart outline with arrows inside.

CORRECT:

          ↑   →   ↑
       →  →  ↓  ←  ←
     ↓  →  →  ←  ←  ↓
     →  ↓  ↑  →  ↓  →
      ←  →  ↓  ←  →
        ↓  →  ←  ↓
          →  ↓  ←
             ↓

The actual arrows occupy the area of the heart.

The collection of arrow pieces creates the heart silhouette.

Every arrow is an individual piece.

An arrow consists of:

- rectangular/rounded shaft
- one arrowhead
- optionally one or more 90-degree turns
- consistent thickness
- clearly defined beginning and end

    │
    │
    ↓

==================================================
7. SILHOUETTE = OCCUPANCY MASK
==================================================

Internally represent every target picture as a binary mask:

WHITE = area where arrow pieces may exist

BLACK = outside the silhouette

For example:

HEART MASK:

      00111100
    01111111110
   111111111111
   111111111111
    1111111111
     11111111
       1111
        11

The level generator must place arrow pieces inside this mask.

The final union of all arrow pieces should approximate this mask.

The arrows themselves become the visible silhouette.

11. BLOCKING MECHANIC
==================================================

The core puzzle mechanic must be based on the arrow's entire escape path.

If an arrow points RIGHT:

    ───────────────▶

extend its movement direction beyond its arrowhead.

If another active arrow is in that direction:

    ───────────────▶
             █████████

the arrow is BLOCKED.

If nothing is in its way:

    ───────────────▶          OUT

it can escape.

When tapped:

    ───────────────▶  →  →  →

the entire arrow piece moves out of the puzzle.

24. PROCEDURAL GENERATION
==================================================

Implement the generator in these stages:

1. Load target silhouette.
2. Convert silhouette to binary mask.
3. Erode the mask slightly to account for arrow thickness.
4. Divide usable area into an invisible logical grid.
5. Select starting locations.
6. Generate horizontal/vertical arrow paths.
7. Allow 90-degree turns.
8. Keep each path inside the mask.
9. Ensure minimum spacing.
10. Continue until sufficient silhouette coverage exists.
11. Calculate coverage.
12. Compare generated coverage to target mask.
13. Reject poor silhouettes.
14. Build blocking relationships.
15. Assign arrow directions.
16. Run puzzle solver.
17. Reject unsolvable levels.
18. Calculate difficulty.
19. Save valid level.

==================================================
27. SOLVER
==================================================

Implement a solver that understands the exact same collision rules as gameplay.

For every state:

1. Find all currently unblocked arrows.
2. Try removing each.
3. Generate the resulting state.
4. Search recursively.
5. Continue until all arrows are removed.

The generator must reject any level where:

active arrows > 0

AND

available arrows == 0.
